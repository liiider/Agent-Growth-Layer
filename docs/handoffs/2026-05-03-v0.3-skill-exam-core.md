# Handoff: V0.3 Skill and Exam Core

Date: 2026-05-03

## Scope

Implemented the V0.3 core promotion loop:

- `POST /v1/skills/build`
- `GET /v1/skills`
- `GET /v1/skills/{id}`
- `PATCH /v1/skills/{id}`
- `PATCH /v1/skills/{id}/status`
- `POST /v1/skills/{skill_id}/exam`
- SQLite persistence for skills and exams
- `latest_exam` on skill responses
- Candidate skill promotion to `verified`
- Failed exam transition to `failed`
- Verified skills entering `POST /v1/guidance`

## Intended Effect

Developers can now:

1. Submit experience and generate cognition.
2. Build a candidate skill from cognition IDs.
3. Run a manual-score exam.
4. Promote passing skills to verified.
5. Request guidance again and receive verified guidance.

## Implementation Notes

- Skill builder currently derives procedure and constraints directly from cognitions.
- Exam runner supports a deterministic `manual_score` path.
- `llm_judge` is accepted as an evaluator label, but no external LLM call is made yet.
- Passing threshold is `0.75`.
- `GET /v1/skills/{id}` returns the latest exam.
- Verified skills are read during guidance assembly and returned in `verified_skills`.
