# Handoff: V0.2 Experience Learning Core

Date: 2026-05-03

## Scope

Implemented the core V0.2 learning loop:

- `POST /v1/experiences`
- `GET /v1/experiences/{id}`
- `POST /v1/experiences/{id}/extract`
- `GET /v1/cognitions`
- `GET /v1/cognitions/{id}`
- `PATCH /v1/cognitions/{id}/status`
- SQLite persistence for experiences and cognitions
- FastAPI `BackgroundTasks` extraction
- Candidate cognition generation with `evidence_refs`
- Candidate guidance returned by the next `POST /v1/guidance`
- Python SDK `client.experiences.create(...)`

This stage intentionally did not implement:

- Feedback API
- Prompt Import API
- JavaScript/TypeScript SDK
- LLM-based extraction
- Skill build
- Exam
- Audit API

Those remain for later V0.2/V0.3 stages.

## Intended Effect

Developers can now:

1. Get seed guidance.
2. Submit a real task experience with feedback.
3. Let the server extract a candidate cognition in the background.
4. Query the stored experience and cognition.
5. Request guidance again and receive candidate guidance with:
   - `status: candidate`
   - `weight`
   - `confidence`
   - `evidence_refs`

## Implementation Notes

- Extraction currently uses a deterministic local extractor, not an LLM.
- This keeps tests stable and preserves the no-model-call guidance hot path.
- For corrected/failed experiences, the extractor emits `error_pattern` cognition.
- For other experiences, the extractor emits `rule` cognition.
- `weight` is derived from `risk_level`.
- Manual extraction retry sets status to `retrying`, then replaces existing cognitions for the same experience to avoid duplicate candidate guidance.

## Problems Encountered

1. SQLite could not open `./data/agent_growth_layer.db` after generated files were moved to `D:\temp`.
   - Cause: repository code assumed the database directory already existed.
   - Fix: storage connection now ensures the database parent directory exists; repositories also initialize schema on construction.
   - Verification: `python -m pytest tests/test_experience_learning.py`.

2. Full test suite was polluted by shared local SQLite state.
   - Symptom: cold-start guidance test unexpectedly returned prior candidate skills.
   - Fix: added an autouse pytest fixture that assigns a fresh temporary SQLite database per test and clears `get_settings()` cache.
   - Verification: full suite now passes deterministically.

3. Manual extraction retry could create duplicate cognitions for the same experience.
   - Risk: repeated retry would pollute guidance with duplicate candidates.
   - Fix: extractor deletes existing cognitions for that experience before creating the replacement candidate.
   - Verification: retry test asserts a single cognition id after retry.

4. Real HTTP validation returned more candidates than expected because previous manual local runs used the persistent default database.
   - Cause: real local `data/` persisted outside isolated tests.
   - Fix for repo: tests are isolated; generated local `data/` is moved to `D:\temp` after verification.
   - Operational note: local developers can reset by moving `data/` to `D:\temp`.
